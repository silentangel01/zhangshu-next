# 章枢 UI/UX 设计规范 v2

## 0. 文档定位

本文档用于约束章枢后续 UI/UX 改造。它不是功能需求文档，也不是视觉稿，而是给后续开发、Codex 修改、人工审查共同遵守的界面设计准则。

本阶段的核心目标是：在不继续膨胀功能的前提下，把章枢从“功能丰富的开发原型”打磨为“作者愿意长期打开使用的本地写作软件”。

后续所有 UI 改动应优先遵守本文档。若某次改动与本文档冲突，应先更新本文档，再改代码。

---

## 1. 设计目标

章枢是一款面向长篇创作的写作应用，不是管理后台，也不应给用户造成“正在操作一套复杂系统”的心理负担。界面需要优先服务持续写作、快速查阅资料、低打断保存和稳定创作节奏。

本规范的目标是：

- 让用户进入项目后尽快开始写作。
- 让资料、规划、检查、统计等能力围绕写作展开。
- 控制页面噪声，减少“功能很多但难以使用”的感受。
- 建立统一的颜色、布局、按钮、卡片、表单、状态和文案规则。
- 为后续 UI 改造提供统一准则，避免模块各自生长造成风格失控。

章枢的界面目标可以概括为：**安静、清楚、可靠、适合长时间写作**。

---

## 2. 用户定位与核心场景

### 2.1 用户定位

章枢的主要用户包括：

- 网络小说作者。
- 长篇故事写作者。
- 需要持续管理世界观、角色、伏笔和剧情结构的创作者。
- 有本地写作、安全保存、导出备份需求的作者。

### 2.2 核心场景

章枢需要优先服务以下场景：

- 日常写作。
- 分卷与章节管理。
- 写作时查阅人物、设定、伏笔、细纲。
- 大纲规划与章节绑定。
- 人物 / 设定 / 伏笔资料维护。
- 时间轴与关系图维护。
- 导出、备份、检查、搜索、统计等工具操作。

其中，**日常写作是第一优先级**。其他场景都不应反过来压制写作体验。

## 3. 总体设计原则

### 3.1 写作为中心

写作工作区必须把正文编辑放在视觉和交互中心。任何资料、工具、提醒都不应喧宾夺主。

### 3.2 资料为辅助

人物、设定、伏笔、时间轴、关系图等模块是写作辅助，而不是主角。写作页展示的是“当前章节所需的核心信息”，不是完整资料库。

### 3.3 完整页面负责管理，写作侧栏负责查看

- 完整资料页负责创建、编辑、删除、绑定、交叉维护。
- 写作侧栏负责展示当前章节的精简摘要。
- 不要在写作页侧栏重复搭建完整资料维护界面。

### 3.4 常用操作外露，不常用操作收起

- 常用操作应直接可见，例如保存、字号、行距、折叠侧栏。
- 低频操作放入“更多”“下拉菜单”“二级面板”。
- 避免把所有功能并排暴露在主界面上。

### 3.5 减少解释性文案

界面不应依赖大段提示来解释自己。优先通过合理的信息结构、短标签和清晰层级表达用途。

### 3.6 保持本地优先和安全感

章枢强调本地优先。UI 需要持续传递“内容在本地、保存可预期、恢复可控、操作可回退”的安全感。

### 3.7 保持中文界面简洁

- 使用短中文标签。
- 避免技术化措辞。
- 避免重复术语和过长按钮文案。

## 4. 信息架构原则

### 4.1 页面分类

章枢页面分为五类：

- 写作工作区。
- 完整资料页。
- 画布页。
- 工具页。
- 项目页。

### 4.2 写作工作区

写作工作区是正文创作中心，不应膨胀成完整资料管理页。

### 4.3 完整资料页

完整资料页负责维护模块自身数据，以及跨模块绑定关系。

### 4.4 画布页

时间轴画布与关系图画布用于空间化组织信息，应强调选择、查看、调整和检查，不承担过多表格式管理。

### 4.5 工具页

统计、检查、导入导出、备份恢复、搜索等属于任务型页面，应围绕“完成一次明确任务”组织交互。

### 4.6 项目页

项目页负责承载进入写作、进入资料模块、进入工具模块的主导航责任。

### 4.7 核心边界

必须明确以下边界：

- 写作工作区不负责全面资料管理。
- 完整模块页负责跨模块链接维护。
- 写作辅助面板只展示当前章节核心摘要。

## 5. 写作工作区规范

### 5.1 三栏结构

写作工作区采用稳定的三栏结构：

- 左侧：分卷 / 章节树。
- 中间：章节编辑器与写作状态。
- 右侧：精简写作辅助。

### 5.2 左侧面板规范

左侧面板只负责：

- 项目标题。
- 分卷 / 章节树。
- 新建分卷。
- 新建章节。

不应长期放置搜索、检查、导出、备份等项目级导航按钮。

### 5.3 中间编辑区规范

中间区域只保留：

- 当前章节主标题。
- 编辑器工具栏。
- 正文编辑区。
- 状态行。

避免重复展示章节标题、章节摘要、解释性帮助语。

### 5.4 右侧写作辅助规范

右侧只展示与当前章节直接相关的精简资料摘要，不出现复杂关联维护表单。

### 5.5 顶部工具栏规范

顶部工具栏负责项目级动作，例如：

- 返回项目列表。
- 搜索。
- 检查。
- 统计。
- 更多。

不应与章节树功能混杂。

### 5.6 折叠与展开

- 左右侧栏都应支持折叠 / 展开。
- 折叠后保留细窄可点击展开控件。
- 展开 / 收起应有 180ms 到 240ms 的平滑动画。
- 折叠状态应可恢复。
- 折叠动画只改变布局和可见性，不应销毁当前章节、资料 Tab 或编辑器状态。

### 5.7 编辑器工具栏位置

常用编辑器显示设置应位于正文上方，保持轻量、紧凑、可快速调整。

常用设置包括：

- 字号。
- 行距。
- 首行缩进。
- 编辑宽度。
- 保存。

不常用设置进入“更多设置”。

### 5.8 写作状态行

状态行保持一行、轻量、不打断：

- 当前字数。
- 今日字数。
- 本小时。
- 本次写作。
- 速度。
- 上次保存 / 保存状态。

面向作者的“字数”默认指净增字数，不强调工程化的新增 / 删除字段。

### 5.9 空状态

未选择章节时，应明确提示下一步，例如“请选择章节开始写作”，而不是展示复杂项目数据墙。

### 5.10 刷新后的状态恢复

刷新页面后应尽量恢复：

- 当前选中章节。
- 左右侧栏折叠状态。
- 右侧辅助当前 tab。
- 编辑器显示设置。

### 5.11 右侧各 Tab 内容规范

#### 大纲

显示：

- 本章细纲。
- 写作目标。
- 状态。
- 完整大纲入口。

不显示完整跨模块展开数据。

#### 人物

显示：

- 本章人物。
- 关系类型。
- 角色定位。
- 简介 / 备注。
- 人物库入口。

#### 设定

显示：

- 本章设定。
- 类型 / 状态。
- 简介。
- 设定集入口。

#### 伏笔

显示：

- 本章伏笔。
- 埋设 / 推进 / 回收关系。
- 状态。
- 回收计划。
- 伏笔库入口。

#### 时间轴

显示：

- 本章事件。
- 前置 / 并行 / 后续事件。
- 完整时间轴入口。

#### 关系图

显示：

- 本章核心关系摘要。
- 直接关系。
- 完整关系图入口。

#### 版本

显示：

- 版本列表。
- 创建快照。
- 恢复。

## 6. 完整资料页规范

### 6.1 通用布局

完整资料页建议遵循统一结构：

- 顶部 Header。
- 左侧列表 / 树 / 筛选。
- 中间详情编辑区。
- 右侧关联资料面板（如确有需要）。

### 6.2 职责边界

完整资料页负责：

- 创建资料。
- 编辑资料。
- 删除资料。
- 建立绑定。
- 维护跨模块关系。
- 跳转相关模块。

写作页不重复承担这些职责。

### 6.3 大纲页

负责：

- 大纲条目编辑。
- 条目层级维护。
- 状态维护。
- 与章节、人物、设定、伏笔、时间轴事件的显式关联维护。

### 6.4 人物页

负责：

- 人物资料编辑。
- 人物与章节 / 大纲 / 伏笔 / 时间轴 / 关系图节点等的关联维护。

### 6.5 设定页

负责：

- 设定资料编辑。
- 设定状态维护。
- 与章节 / 大纲 / 伏笔 / 时间轴 / 关系图节点等的关联维护。

### 6.6 伏笔页

负责：

- 伏笔生命周期维护。
- 埋设 / 推进 / 回收阶段维护。
- 与章节 / 人物 / 设定 / 大纲 / 时间轴等的关联维护。

### 6.7 时间轴页

负责：

- 事件编辑。
- 轨道管理。
- 事件时序关系维护。
- 与章节 / 大纲 / 人物 / 设定 / 伏笔 / 关系图的显式关联维护。

### 6.8 关系图页

负责：

- 节点与连线编辑。
- 绑定资料。
- 打开绑定资料。
- 从绑定资料同步节点信息。

---

## 7. 工具页规范

适用页面：

- 统计。
- 检查 / 审阅。
- 导入导出。
- 备份恢复。
- 搜索。

原则如下：

- 任务导向。
- 主操作明确。
- 解释文案最小化。
- 结果或报告清晰。
- 危险操作必须有确认。

工具页不应像资料页那样堆积大量长期可编辑信息。

---

## 8. 画布页规范

适用页面：

- 时间轴画布。
- 关系图画布。

### 8.1 工具栏分组

画布工具栏应按功能分组：

- 视图。
- 创建。
- 排布。
- 筛选。
- 显示模式。

### 8.2 平移与缩放

- 鼠标和触控行为应稳定。
- 缩放反馈清晰。
- 不因打开侧边面板导致画布错位。
- 画布必须监听容器尺寸变化；浏览器窗口、桌面窗口、Inspector 面板和侧栏变化后，应重新计算节点与连线位置。

### 8.3 节点选择

- 节点选中态必须清楚。
- 选中节点后 Inspector 内容应稳定更新。

### 8.4 连线选择

- 连线应可点击。
- 细线需要更宽点击热区。
- 选中态与普通态清楚区分。

### 8.5 Inspector 面板

- Inspector 负责查看和编辑当前选中对象。
- 只展示与当前对象直接相关的字段。

### 8.6 右键菜单

- 只保留与当前对象相关的动作。
- 不要把全局操作塞进对象菜单。

### 8.7 清爽模式

清爽模式应弱化边框、辅助线、标签干扰，让用户聚焦结构本身。

### 8.8 网格与吸附

- 如有网格与吸附，交互语言需统一。
- 不应让用户猜测当前位置是否已对齐。

### 8.9 避免杂乱

画布页优先保证可读性，不追求一次展示全部信息。

## 9. 组件规范

### 9.1 按钮

- 主要按钮只用于当前页面最重要动作。
- 次级按钮数量要受控。
- 文案短、动词明确。

### 9.2 图标按钮

- 优先用于折叠、展开、关闭、刷新、更多等通用动作。
- 必要时带 tooltip。

### 9.3 Tabs

- Tab 名称保持短。
- 用于平级内容切换，不承担复杂导航。

### 9.4 卡片

- 只用于信息分组。
- 不要把整个页面做成一堆大卡片。
- 卡片内容应短小、可扫读。

### 9.5 表单

- 字段分组清楚。
- 必填项明确。
- 错误信息贴近字段。

### 9.6 Select / Dropdown

- 常用筛选和枚举值使用下拉。
- 文案需可快速扫读。

### 9.7 Popover

- 用于轻量附加选项。
- 不承载大块复杂内容。
- 点击外部或按 Escape 应关闭。

### 9.8 Modal

- 用于确认、预览、一次性任务。
- 不要把长期编辑器塞进弹窗。

### 9.9 Context Menu

- 面向当前对象。
- 动作数量克制。
- 危险项靠后并明确标识。

### 9.10 Badge / Tag

- 用于状态、类型、重要程度。
- 颜色编码应稳定一致。

### 9.11 状态标签

保存中、已保存、草稿、已定稿、已回收等状态，应使用统一视觉语言，不要每页自创一套。

### 9.12 空状态

空状态要短、可行动，例如：

- 本章暂无人物。
- 可在完整资料库中维护。

### 9.13 加载状态

- 局部加载优先局部骨架或轻提示。
- 不要动不动整页白屏。

### 9.14 错误状态

- 错误信息简洁。
- 能重试的给出重试入口。
- 不用技术堆栈信息吓用户。

## 10. 视觉规范与主题颜色

### 10.1 视觉方向

章枢的视觉方向是“安静的创作工作台”，不是高饱和后台系统，也不是娱乐化工具。主题颜色应服务长时间写作：低刺激、对比清楚、层级稳定。

推荐关键词：

- 纸感。
- 墨色。
- 青蓝。
- 低饱和。
- 稳定。
- 长时间可读。

### 10.2 默认主题：墨青纸白

默认主题建议使用“墨青纸白”作为品牌基础主题。

用途定位：日常写作、默认启动、浅色模式。

核心色板：

| Token | 建议值 | 用途 |
|---|---:|---|
| `--color-bg` | `#F6F8F7` | 应用背景 |
| `--color-surface` | `#FFFFFF` | 卡片、面板、输入区 |
| `--color-surface-soft` | `#F0F5F3` | 弱背景、折叠栏、轻提示 |
| `--color-text` | `#1F2A2E` | 主文字 |
| `--color-text-muted` | `#6B7C83` | 次级文字 |
| `--color-text-faint` | `#95A3A8` | 占位、辅助说明 |
| `--color-primary` | `#2F6F73` | 主按钮、选中态、关键入口 |
| `--color-primary-hover` | `#285F63` | 主色 hover |
| `--color-primary-soft` | `#DCECEC` | 主色弱背景 |
| `--color-accent` | `#B88746` | 少量强调、统计重点 |
| `--color-border` | `#D9E2E0` | 边框 |
| `--color-border-strong` | `#BAC9C6` | 强边框、选中轮廓 |

主题说明：

- `primary` 选择偏墨青色，而不是纯蓝，降低后台感。
- `accent` 使用低饱和金棕，只用于极少数强调，不应大面积铺开。
- 背景不使用纯白铺满，应保留轻微纸感。

### 10.3 护眼主题：暖纸杏白

用途定位：长时间写作、夜间但不想使用深色模式的用户。

核心色板：

| Token | 建议值 | 用途 |
|---|---:|---|
| `--color-bg` | `#F8F3E8` | 应用背景 |
| `--color-surface` | `#FFF9EF` | 编辑器、卡片 |
| `--color-surface-soft` | `#F1E7D6` | 轻背景 |
| `--color-text` | `#2D261F` | 主文字 |
| `--color-text-muted` | `#7A6A57` | 次级文字 |
| `--color-primary` | `#6D7F5F` | 主按钮、选中态 |
| `--color-primary-soft` | `#E3E9D8` | 主色弱背景 |
| `--color-accent` | `#A66A3F` | 强调 |
| `--color-border` | `#E0D2BC` | 边框 |

主题说明：

- 护眼主题避免偏黄过重，否则会显旧、显脏。
- 编辑器正文区应比页面背景略亮，形成纸张层次。

### 10.4 深色主题：夜墨青蓝

用途定位：夜间写作、低亮度环境。

核心色板：

| Token | 建议值 | 用途 |
|---|---:|---|
| `--color-bg` | `#11181B` | 应用背景 |
| `--color-surface` | `#182225` | 卡片、面板 |
| `--color-surface-soft` | `#202D31` | 次级面板 |
| `--color-text` | `#E7ECEA` | 主文字 |
| `--color-text-muted` | `#A7B4B1` | 次级文字 |
| `--color-text-faint` | `#6F7D7B` | 占位、弱提示 |
| `--color-primary` | `#6EB7B8` | 主按钮、选中态 |
| `--color-primary-hover` | `#87C9C9` | 主色 hover |
| `--color-primary-soft` | `#213B3E` | 主色弱背景 |
| `--color-accent` | `#D0A15D` | 少量强调 |
| `--color-border` | `#2B3A3F` | 边框 |
| `--color-border-strong` | `#3D555B` | 强边框 |

主题说明：

- 深色主题不使用纯黑，避免正文对比刺眼。
- 正文编辑区和侧栏要有层级，但不能用高亮边框堆叠。

### 10.5 状态色规范

状态色必须稳定，不允许每个模块自定义。

| 状态 | Token | 浅色建议 | 深色建议 | 用途 |
|---|---|---:|---:|---|
| 成功 | `--color-success` | `#3B8A5A` | `#7BC99A` | 已保存、完成、已回收 |
| 警告 | `--color-warning` | `#B8871F` | `#E0B85B` | 未完成、草稿、需注意 |
| 危险 | `--color-danger` | `#C24A4A` | `#E27777` | 删除、失败、严重问题 |
| 信息 | `--color-info` | `#4E78A8` | `#8DB7E3` | 提示、说明、普通提醒 |

使用规则：

- 保存成功使用成功色，但只做轻量提示。
- 删除、恢复覆盖、清空数据使用危险色。
- 草稿、未定稿、未回收使用警告色，但不应过分刺眼。
- 普通说明不使用高饱和蓝。

### 10.9 间距 Token

建议统一间距梯度：

| Token | 值 | 用途 |
|---|---:|---|
| `--space-1` | `4px` | 小图标间距、标签内距 |
| `--space-2` | `8px` | 按钮组、表单小间距 |
| `--space-3` | `12px` | 卡片内部基础间距 |
| `--space-4` | `16px` | 面板内距 |
| `--space-5` | `20px` | 页面区块间距 |
| `--space-6` | `24px` | 大区块间距 |
| `--space-8` | `32px` | 页面主段落间距 |

### 10.10 圆角

| Token | 值 | 用途 |
|---|---:|---|
| `--radius-sm` | `4px` | 标签、紧凑按钮 |
| `--radius-md` | `8px` | 输入框、普通按钮、卡片 |
| `--radius-lg` | `12px` | 重要面板、弹窗 |
| `--radius-pill` | `999px` | 徽章、胶囊按钮 |

常规组件圆角建议 6px 到 8px，保持克制，不追求夸张圆润。

### 10.11 阴影

阴影只用于层级提示，不用于装饰。

| Token | 建议值 | 用途 |
|---|---|---|
| `--shadow-sm` | `0 1px 2px rgba(15, 23, 42, 0.06)` | 轻微浮起 |
| `--shadow-md` | `0 8px 24px rgba(15, 23, 42, 0.10)` | Popover / Modal |
| `--shadow-focus` | `0 0 0 3px var(--color-primary-soft)` | 聚焦态 |

### 10.12 排版

- 标题层级清楚。
- 正文易读。
- 小字状态信息保持可见但不抢眼。
- 写作区字体设置可本地切换，但不影响正文存储。

建议字号：

| 类型 | 字号 | 用途 |
|---|---:|---|
| 页面标题 | `24px` | 项目页、资料页标题 |
| 区块标题 | `18px` | 主要内容区 |
| 卡片标题 | `15px - 16px` | 卡片内部标题 |
| 正文 UI | `14px` | 表单、列表、说明 |
| 状态文字 | `12px - 13px` | 保存状态、提示、标签 |
| 编辑器正文 | `16px - 20px` | 用户可调 |

### 10.13 字体策略

- 中文默认优先系统字体和本机字体。
- 不强依赖特定商业字体。
- 写作区字体设置可本地切换，但不影响正文存储。
- 字体通过 CSS `font-family` 调用本机已安装字体，不随软件分发 Windows、macOS 或其他专有字体文件。

### 10.14 护眼 / 深色模式原则

- 以长时间写作为前提。
- 对比度充足。
- 不追求炫技配色。
- 护眼模式不应过黄。
- 深色模式不应纯黑高反差。

## 11. 交互规范

### 11.1 点外关闭

Popover 打开后，点击外部应关闭。

### 11.2 Escape 关闭

Popover、Modal、Context Menu 打开时，按 `Escape` 应关闭。

### 11.3 危险操作确认

以下操作必须确认：

- 删除。
- 恢复旧版本。
- 覆盖导入。
- 恢复备份。

### 11.4 Autosave 状态轻量化

自动保存状态应该轻量显示，不应频繁弹出提示打断写作。

### 11.5 拖拽反馈

树、节点、连线、画布拖拽都应有明确反馈，避免用户不确定是否生效。

### 11.6 折叠 / 展开动画

工作区和侧栏折叠 / 展开需要平滑、快速、低干扰。

### 11.7 不阻断写作流

写作过程中避免频繁 toast、模态打断和噪声提醒。

## 17. Web 与桌面窗口适配规范

### 17.1 基本原则

章枢采用“桌面优先，但不是固定尺寸”的布局策略。

- UI 不应只适配某一张 1920×1080 截图。
- 测试版在浏览器中运行，浏览器地址栏、缩放比例和窗口大小都会影响实际可用区域。
- 正式桌面版未来会运行在独立软件窗口中，窗口大小也会变化。
- 正文编辑区永远是最高优先级区域。
- 所有主页面都应避免全局横向滚动条；必要滚动应限制在局部列表、表格、画布或内容区域内。

### 17.2 推荐窗口尺寸

建议按以下窗口尺寸设计和测试：

| 等级 | 尺寸 | 说明 |
|---|---:|---|
| 最低可用 | 1280 × 720 | 必须能完成选择章节、写作、保存等核心流程。 |
| 推荐最低 | 1366 × 768 | 普通笔记本常见尺寸，应能稳定使用。 |
| 舒适尺寸 | 1440 × 900 | 推荐桌面窗口默认尺寸。 |
| 宽屏体验 | 1600 × 900 以上 | 可以展示完整三栏、更多画布空间和工具区。 |

低于 1280px 宽度时，应进入紧凑模式；不应为了维持完整三栏而挤压正文编辑区。

### 17.3 响应式断点

章枢前端建议使用以下断点：

| 模式 | 宽度范围 | 行为 |
|---|---:|---|
| Compact | `< 1100px` | 默认收起右侧资料面板，左侧章节树可手动收起，正文区域优先保留。 |
| Standard | `1100px - 1439px` | 保持三栏布局，但左右栏可使用较窄宽度，顶部工具栏减少长文案。 |
| Wide | `>= 1440px` | 完整三栏，资料面板、章节树、画布 Inspector 可以正常展开。 |

Compact 模式下，顶部工具栏应优先使用短标签、图标按钮或“更多”菜单，不应把所有入口横向平铺。

### 17.4 写作工作区尺寸规则

写作工作区建议采用以下尺寸范围：

- 左侧章节树默认宽度：`240px - 280px`。
- 右侧资料面板默认宽度：`300px - 340px`。
- 折叠栏宽度：`40px - 48px`。
- 中间编辑区最小可用宽度：`560px`。
- 正文文本最大阅读宽度：`760px - 920px`。

布局规则：

1. 当窗口变窄时，优先收起右侧资料面板。
2. 其次允许收起左侧章节树。
3. 不允许正文编辑区被压缩到难以写作。
4. 正文输入区不应在超宽屏上无限拉伸，应保持舒适阅读宽度并居中或形成自然留白。
5. 左右栏折叠 / 展开时，中间编辑区应平滑扩展，不应跳变。
6. 浏览器缩放到 125% 时，保存、章节选择、写作统计等核心操作仍应可见。

### 17.5 资料页尺寸规则

完整资料页建议采用“列表 / 详情 / 关联资料”的可变布局：

- 左侧列表区：`260px - 320px`。
- 中间详情区：自适应，优先保证表单字段可读。
- 右侧关联资料区：`280px - 340px`。

窄窗口下：

1. 右侧关联资料区可折叠，或移动到详情区下方。
2. 左侧列表可变成顶部筛选 + 列表抽屉。
3. 表单字段不应横向挤压到不可读。
4. 详情编辑区应优先保留完整字段标签和输入框。

### 17.6 画布页尺寸规则

适用于时间轴和关系图画布。

- 画布区域应填满除工具栏、侧栏、Inspector 之外的剩余空间。
- 工具栏高度应稳定，不能随着窗口尺寸剧烈变化。
- Inspector 面板应可折叠。
- 画布必须监听容器尺寸变化。
- 打开 / 关闭 Inspector、浏览器缩放、窗口拖拽缩放、侧栏折叠后，节点和连线应重新计算。
- 不允许因窗口变化导致时间轴或关系图连线错位。
- 推荐使用 `ResizeObserver` 或等价机制监听容器变化。

画布页不应依赖全局窗口尺寸计算节点位置，而应以画布容器尺寸为准。

### 17.7 工具页尺寸规则

适用于统计、检查、导入导出、备份恢复、搜索等页面。

- 使用居中内容容器。
- 宽屏下不要让文本、表单和报告内容无限拉伸。
- 统计图表可以自适应宽度，但标题、说明和按钮应保持紧凑。
- 小窗口下，多列卡片应变为单列或两列。
- 操作按钮不应挤在一起；必要时转为纵向排列。
- 报告表格可以局部横向滚动，但页面整体不应出现横向滚动。

### 17.8 桌面窗口策略

未来桌面打包版本建议采用：

- 默认窗口：`1440 × 900`。
- 最小窗口：`1280 × 720`。
- 记住上次窗口大小。
- 框架支持时，记住上次窗口位置。
- 启动后恢复用户上次工作状态，包括项目、章节、侧栏、右侧 Tab 和编辑器显示设置。

桌面版规则：

1. 不应依赖固定窗口尺寸。
2. 用户缩放窗口时，布局应平滑适配。
3. 桌面壳中的标题栏、窗口边框、系统缩放都要预留空间。
4. 如果未来使用自定义标题栏，需要单独设计拖拽区域和窗口控制按钮。
5. 软件窗口不应因为内部组件最小宽度过大而无法缩小到最小尺寸。

### 17.9 浏览器测试版注意事项

当前测试版本运行在浏览器中，因此需要额外注意：

- 浏览器地址栏、书签栏会减少实际可用高度。
- 浏览器 100% 和 125% 缩放都需要测试。
- 不应把页面高度写死为某个截图高度。
- 推荐使用 `min-height`、`flex layout`、`overflow: auto` 的组合，而不是硬编码固定高度。
- 开发时不能只以当前显示器截图为准，应至少测试常见窗口宽度。

### 17.10 适配验收清单

每次 UI 改动后，至少检查：

- `1280×720` 下能选择章节并写作。
- `1366×768` 下三栏或紧凑三栏可用。
- `1440×900` 下三栏舒适。
- `1920×1080` 下正文不会无限拉伸。
- 折叠左右栏后正文区域平滑扩展。
- 打开右侧资料栏不会遮挡正文。
- 浏览器缩放 `125%` 后主要操作仍可见。
- 时间轴和关系图调整窗口后连线不偏移。
- 工具页在窄窗口下不会出现全局横向滚动。
- 未来桌面打包窗口下主流程仍可完成。


## 18. Codex UI 修改约束

后续让 Codex 执行 UI 修改时，必须附加以下约束：

1. 不新增业务功能。
2. 不修改数据库结构。
3. 不改动核心 API 合同。
4. 不重构无关模块。
5. 优先使用本文档定义的 CSS Token。
6. 不在页面内硬编码新颜色。
7. 不把写作页改成资料管理页。
8. 不把完整资料页的复杂维护表单塞进写作右栏。
9. 改动后必须检查中文显示、构建、主要页面导航。
10. 所有危险操作必须保留确认。
11. 不允许只按单一截图尺寸写死宽高。
12. UI 改动必须至少考虑 `1280×720`、`1366×768`、`1440×900`、`1920×1080` 四档窗口。
13. 画布页改动必须验证容器尺寸变化后连线不偏移。
14. 写作页改动必须优先保护正文编辑区宽度。
