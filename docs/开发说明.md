# 开发说明

本文档记录掌书 Next 当前原型阶段的开发约定。

## 运行命令

启动后端：

```powershell
cd C:\dev\zhangshu-next\backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

启动前端：

```powershell
cd C:\dev\zhangshu-next\frontend
npm run dev
```

常用入口：

```text
http://127.0.0.1:8000/docs
http://localhost:5173/projects
```

## 后端约定

- 后端使用 FastAPI + SQLAlchemy + SQLite。
- 开发数据库位于 `data/zhangshu_dev.sqlite3`。
- 当前原型阶段在应用启动时自动创建数据库表。
- 删除项目、分卷、章节时使用 `deleted_at` 软删除。
- 章节正文通过 `PATCH /api/chapters/{chapter_id}` 保存。

## 前端约定

- 前端使用 Vue 3 + TypeScript + Vite。
- API 基地址来自 `VITE_API_BASE_URL=http://127.0.0.1:8000`。
- 当前 UI 默认使用简体中文。
- 暂不引入完整 i18n 框架，界面文案直接写在 Vue 文件中。
- 章节编辑器当前使用原生 `<textarea>`，暂不引入富文本编辑器依赖。

## 自动保存与恢复稿

- 章节正文停止输入约 2 秒后触发自动保存。
- 自动保存调用现有 `PATCH /api/chapters/{chapter_id}`。
- 手动保存会传递 `save_source = "manual"`。
- 自动保存会传递 `save_source = "autosave"`。
- 自动保存失败时，编辑框中的本地内容不会被覆盖。
- 用户编辑时会在 `localStorage` 写入本地恢复稿。
- 恢复稿 key 格式为 `zhangshu:recovery-draft:{chapter_id}`。
- 手动保存或自动保存成功后会清除对应章节的本地恢复稿。
- 当前恢复稿只保存在浏览器本地，不上传到任何外部服务。

## 章节版本历史

- 数据表：`chapter_versions`。
- 版本来源包括：`manual`、`autosave`、`restore`、`before_restore`。
- 手动保存正文且内容变化时，会创建 `manual` 版本。
- 自动保存正文时会节流创建版本：距离上一条版本超过 5 分钟，或正文非空白字符变化达到 200 字以上时，才创建 `autosave` 版本。
- 点击“创建版本快照”会调用 `POST /api/chapters/{chapter_id}/versions`。
- 点击“恢复此版本”会调用 `POST /api/chapters/{chapter_id}/restore-version/{version_id}`。
- 恢复前会先创建 `before_restore` 快照，恢复后会记录 `restore` 快照。
- 当前阶段不实现版本差异对比、完整版本管理页、云备份或同步。

## 导入作品

- 导入页面位于 `http://localhost:5173/imports`。
- 旧版 JSON 导入使用 `POST /api/imports/preview` 预览，确认后使用 `POST /api/imports/{import_id}/confirm` 写入数据库。
- 文件夹压缩包导入支持 `.zip`，压缩包内支持 `.txt` 和 `.md`。
- 文件夹结构中，顶层目录会作为项目名候选，第一层文件夹会作为分卷，文本文件会作为章节。
- 平铺在项目根目录下的 `.txt` / `.md` 会作为未分卷章节导入。
- 章节和分卷按自然排序处理，例如 `1`、`2`、`10` 会按数字顺序排列。
- 文本编码按 `UTF-8`、`UTF-8-SIG`、`GBK` 的顺序尝试；仍无法读取的文件会记录到失败文件列表。
- 导入流程不会覆盖现有项目；当前只支持确认后创建一个新项目。
- 导入预览文件保存在 `data/imports/`，临时解压文件保存在 `data/imports/tmp/`，导入报告保存在 `data/imports/reports/`。
- 当前暂不导入人物、关系图、时间线、知识库等复杂资料，后续版本再补。

## 大纲与细纲

- 基础大纲模块使用 `outline_items` 数据表。
- 大纲条目属于项目，可以通过 `parent_id` 形成树形层级。
- 大纲条目可以绑定 `volume_id` 或 `chapter_id`，用于把规划内容挂到分卷或章节上。
- 条目类型包括 `book_outline`、`volume_outline`、`chapter_outline`、`scene`、`plot_point`、`note`。
- 状态包括 `planned`、`writing`、`done`、`abandoned`。
- 重要程度包括 `normal`、`important`、`critical`。
- 项目大纲页路由为 `/projects/{project_id}/outlines`。
- 项目大纲接口包括 `GET /api/projects/{project_id}/outlines`、`POST /api/projects/{project_id}/outlines`、`GET /api/outlines/{outline_id}`、`PATCH /api/outlines/{outline_id}`、`DELETE /api/outlines/{outline_id}`。
- 章节编辑器旁的“当前章节细纲”调用 `GET /api/chapters/{chapter_id}/outlines`，会显示绑定到当前章节的大纲条目及其子条目。
- 当前阶段不实现 AI 生成、拖拽排序、角色/设定/线索联动或图谱视图。

## 编码与路径

- 所有源文件和文档都应使用 UTF-8。
- 避免保存为 GBK/ANSI。
- 避免把项目放在中文路径或 OneDrive 同步路径中，尤其是在遇到编码、权限或文件锁问题时。
- 推荐路径：`C:\dev\zhangshu-next`
